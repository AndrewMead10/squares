# Cloudflare Web App Template Design

## Overview

A full-stack web application template for Cloudflare Workers with type-safe RPC, authentication, and modern tooling.

---

## Technology Stack

| Layer | Technology |
|-------|------------|
| Frontend Runtime | Bun (tooling, dev server, builds) |
| Frontend Framework | TanStack Router + React |
| Styling | Tailwind CSS |
| State Management | TanStack Query |
| Backend | Hono on Cloudflare Workers |
| RPC | hono/client (type-safe) |
| Database | Cloudflare D1 OR PlanetScale via Hyperdrive (user choice at project creation) |
| ORM | Drizzle + Drizzle Kit |
| Validation | Zod |
| Auth | Better Auth (Google OAuth) |
| Session Storage | Cookies |
| Logging | Axiom |
| AI (optional) | Vercel AI SDK |
| File Storage | Cloudflare R2 (signed URLs for private access) |

## Backend Architecture

### Pages Pattern

Each frontend page has a corresponding file in `backend/pages/` containing all routes used by that page.

**Naming Convention:**
- `GET /api/pages/{page}/data` - Load data for a page (onLoad)
- `POST /api/pages/{page}/{action}` - Handle form submissions (onSubmit)

Note: Actions are flat (e.g., `/update-profile`) not nested (e.g., `/actions/update-profile`) for better Hono RPC type inference.

**Example: `backend/pages/app/index.ts`**
```typescript
import { Hono } from 'hono'
import { zValidator } from '@hono/zod-validator'
import { z } from 'zod'
import { apiSuccess } from '../lib/errors'
import type { Env, Variables } from '../types'

const app = new Hono<{ Bindings: Env; Variables: Variables }>()
  // Load page data (onLoad)
  .get('/data', async (c) => {
    const user = c.get('user')
    return c.json(apiSuccess({ user, items: [] }))
  })
  // Handle form submission (onSubmit)
  .post('/update-profile',
    zValidator('json', z.object({
      name: z.string().min(1).max(100),
    })),
    async (c) => {
      const body = c.req.valid('json')
      return c.json(apiSuccess({ updated: true, name: body.name }))
    }
  )

export default app
```

### Functions Pattern

Shared logic between multiple pages goes in `backend/functions/`.

**Rule:** When adding new functionality, check if it exists in another page file. If so, extract to a function and update both pages to use it.

**Example: `backend/functions/user.ts`**
```typescript
import { db } from '../db'
import { users } from '../db/schema'
import { eq } from 'drizzle-orm'

export async function getUserById(id: string) {
  return db.query.users.findFirst({
    where: eq(users.id, id)
  })
}

export async function updateUserProfile(id: string, data: { name: string }) {
  return db.update(users)
    .set(data)
    .where(eq(users.id, id))
    .returning()
}
```

## API Response Format

All API responses follow a standardized format:

```typescript
// backend/lib/errors.ts

type ApiSuccess<T> = {
  success: true
  data: T
}

type ApiError = {
  success: false
  error: {
    code: string                         // e.g., "VALIDATION_ERROR", "NOT_FOUND", "UNAUTHORIZED"
    message: string                      // Human-readable message
    fieldErrors?: Record<string, string> // Per-field validation errors
    formErrors?: string[]                // Form-level errors
  }
}

type ApiResponse<T> = ApiSuccess<T> | ApiError

// Helper functions
export function apiSuccess<T>(data: T): ApiSuccess<T> {
  return { success: true, data }
}

export function apiError(
  code: string,
  message: string,
  fieldErrors?: Record<string, string>,
  formErrors?: string[]
): ApiError {
  return {
    success: false,
    error: { code, message, fieldErrors, formErrors }
  }
}

// Common error codes
export const ErrorCodes = {
  VALIDATION_ERROR: 'VALIDATION_ERROR',
  NOT_FOUND: 'NOT_FOUND',
  UNAUTHORIZED: 'UNAUTHORIZED',
  FORBIDDEN: 'FORBIDDEN',
  INTERNAL_ERROR: 'INTERNAL_ERROR',
  RATE_LIMITED: 'RATE_LIMITED',
} as const
```

## Authentication

### Better Auth Configuration

```typescript
// backend/lib/auth.ts
import { betterAuth } from 'better-auth'
import { drizzleAdapter } from 'better-auth/adapters/drizzle'
import { db } from '../db'

export const auth = betterAuth({
  database: drizzleAdapter(db, {
    provider: 'sqlite' // or 'mysql' for PlanetScale
  }),
  socialProviders: {
    google: {
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
    }
  },
  session: {
    cookieCache: {
      enabled: true,
      maxAge: 60 * 5 // 5 minutes
    }
  }
})
```

### Auth Middleware

```typescript
// backend/middleware/auth.ts
import { createMiddleware } from 'hono/factory'
import { auth } from '../lib/auth'
import { apiError } from '../lib/errors'

export const requireAuth = createMiddleware(async (c, next) => {
  const session = await auth.api.getSession({ headers: c.req.raw.headers })

  if (!session) {
    return c.json(apiError('UNAUTHORIZED', 'Authentication required'), 401)
  }

  c.set('user', session.user)
  c.set('session', session.session)
  await next()
})
```

## Rate Limiting

Global rate limiting for all endpoints (5 requests per second per IP):

```typescript
// backend/middleware/rateLimit.ts
import { createMiddleware } from 'hono/factory'
import { rateLimiter } from 'hono-rate-limiter'
import { apiError } from '../lib/errors'

export const globalRateLimit = rateLimiter({
  windowMs: 1000, // 1 second
  limit: 5,       // 5 requests per window
  keyGenerator: (c) => c.req.header('cf-connecting-ip') || 'unknown',
  handler: (c) => {
    return c.json(apiError('RATE_LIMITED', 'Too many requests'), 429)
  }
})
```

## Security

### CSP Headers

```typescript
// backend/middleware/csp.ts
import { createMiddleware } from 'hono/factory'

export const cspHeaders = createMiddleware(async (c, next) => {
  await next()
  c.header('Content-Security-Policy', "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'")
  c.header('X-Content-Type-Options', 'nosniff')
  c.header('X-Frame-Options', 'DENY')
  c.header('Referrer-Policy', 'strict-origin-when-cross-origin')
})
```

### Input Validation

All input is validated using Zod at the API boundary via `@hono/zod-validator`. Drizzle provides SQL injection protection via parameterized queries.

### CSRF Protection

Handled automatically by Better Auth using the double-submit cookie pattern.

## File Storage (R2)

### Signed URL Pattern

Private bucket by default. Use signed URLs for secure uploads and downloads:

```typescript
// backend/lib/r2.ts
import { S3Client, GetObjectCommand, PutObjectCommand } from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

export function getR2Client(env: Env) {
  return new S3Client({
    region: 'auto',
    endpoint: `https://${env.CF_ACCOUNT_ID}.r2.cloudflarestorage.com`,
    credentials: {
      accessKeyId: env.R2_ACCESS_KEY_ID,
      secretAccessKey: env.R2_SECRET_ACCESS_KEY,
    },
  })
}

export async function getDownloadUrl(env: Env, key: string, expiresIn = 3600) {
  const client = getR2Client(env)
  const command = new GetObjectCommand({
    Bucket: env.R2_BUCKET_NAME,
    Key: key,
  })
  return getSignedUrl(client, command, { expiresIn })
}

export async function getUploadUrl(env: Env, key: string, expiresIn = 3600) {
  const client = getR2Client(env)
  const command = new PutObjectCommand({
    Bucket: env.R2_BUCKET_NAME,
    Key: key,
  })
  return getSignedUrl(client, command, { expiresIn })
}
```

### Error Boundary

```tsx
// frontend/src/components/ErrorBoundary.tsx
import { Component, ReactNode } from 'react'

interface Props {
  children: ReactNode
  fallback?: ReactNode
}

interface State {
  hasError: boolean
  error?: Error
}

export class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error('Error caught by boundary:', error, errorInfo)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || (
        <div className="flex flex-col items-center justify-center min-h-screen">
          <h1 className="text-2xl font-bold text-red-600">Something went wrong</h1>
          <p className="text-gray-600 mt-2">Please refresh the page or try again later.</p>
        </div>
      )
    }

    return this.props.children
  }
}
```

## Setup Script

The template includes a setup script (`scripts/setup.ts`) that:

1. Prompts user to choose database: **D1** or **PlanetScale**
2. Configures `wrangler.toml` and Drizzle config based on choice
3. Creates the Cloudflare Pages project
4. Sets up environment variables interactively
5. Initializes the database schema

Run with:
```bash
bun run setup
```

## Database Choice

At project creation (via setup script), the user must specify:
- **Cloudflare D1** - SQLite-based, serverless, integrated with Cloudflare
- **PlanetScale** - MySQL-compatible, uses Hyperdrive for connection pooling

The setup script configures Drizzle and wrangler.toml appropriately based on this choice.

- Run `tsc --noEmit` after code changes
