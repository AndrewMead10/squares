## Critical Rules

### 1. Database Choice - Ask at Project Start

At the start of a new project, **always ask the user** which database they want to use:
- **Cloudflare D1** - SQLite-based, serverless, integrated with Cloudflare
- **PlanetScale** - MySQL-compatible, uses Hyperdrive for connection pooling

Run `bun run setup` to configure the project based on this choice.

### 2. Run Type Checking After Changes

**Always run `bun run typecheck` after making code changes** to ensure type safety across the RPC boundary. The hono/client provides end-to-end type safety, but only if TypeScript passes.

### 3. Extract Shared Functions

**Rule:** When adding new functionality, check if it exists in another page file. If so, extract to `backend/functions/` and update both pages to use it.

Never duplicate logic across page files.

### 4. Follow the Pages Pattern

Each frontend page has a corresponding file in `backend/pages/` containing all routes used by that page.

## Backend Architecture

### Pages Pattern

Each frontend page has a corresponding file in `backend/pages/` containing all routes used by that page.

**Naming Convention:**
- `GET /api/pages/{page}/data` - Load data for a page (onLoad)
- `POST /api/pages/{page}/{action}` - Handle form submissions (onSubmit)

Note: Actions use flat paths (e.g., `/update-profile`) not nested paths (e.g., `/actions/update-profile`) for better Hono RPC type inference.

**Example: `backend/pages/app/index.ts`**
```typescript
import { Hono } from 'hono'
import { zValidator } from '@hono/zod-validator'
import { z } from 'zod'
import { apiSuccess } from '../lib/errors'
import type { Env, Variables } from '../types'

const app = new Hono<{ Bindings: Env; Variables: Variables }>()
  // Load page data (onLoad)
  .get('/data', async (c) => {
    const user = c.get('user')
    return c.json(apiSuccess({ user, items: [] }))
  })
  // Handle form submission (onSubmit)
  .post('/update-profile',
    zValidator('json', z.object({
      name: z.string().min(1).max(100),
    })),
    async (c) => {
      const body = c.req.valid('json')
      return c.json(apiSuccess({ updated: true, name: body.name }))
    }
  )

export default app
```

### Functions Pattern

Shared logic between multiple pages goes in `backend/functions/`.

**Example: `backend/functions/user.ts`**
```typescript
import { db } from '../db'
import { users } from '../db/schema'
import { eq } from 'drizzle-orm'

export async function getUserById(id: string) {
  return db.query.users.findFirst({
    where: eq(users.id, id)
  })
}

export async function updateUserProfile(id: string, data: { name: string }) {
  return db.update(users)
    .set(data)
    .where(eq(users.id, id))
    .returning()
}
```

## API Response Format

All API responses must follow this standardized format:

```typescript
// Success response
type ApiSuccess<T> = {
  success: true
  data: T
}

// Error response
type ApiError = {
  success: false
  error: {
    code: string                         // e.g., "VALIDATION_ERROR", "NOT_FOUND", "UNAUTHORIZED"
    message: string                      // Human-readable message
    fieldErrors?: Record<string, string> // Per-field validation errors
    formErrors?: string[]                // Form-level errors
  }
}
```

**Helper functions in `backend/lib/errors.ts`:**
```typescript
export function apiSuccess<T>(data: T): ApiSuccess<T> {
  return { success: true, data }
}

export function apiError(
  code: string,
  message: string,
  fieldErrors?: Record<string, string>,
  formErrors?: string[]
): ApiError {
  return {
    success: false,
    error: { code, message, fieldErrors, formErrors }
  }
}
```

**Error Codes:**
- `VALIDATION_ERROR` - Input validation failed
- `NOT_FOUND` - Resource not found
- `UNAUTHORIZED` - Authentication required
- `FORBIDDEN` - Insufficient permissions
- `INTERNAL_ERROR` - Server error

## Authentication

### Better Auth Setup

- Uses Google OAuth for authentication
- Sessions stored in cookies
- Cookie caching enabled (5 minutes)

### Auth Middleware

Use `requireAuth` middleware for protected routes:
```typescript
import { requireAuth } from '../middleware/auth'

const app = new Hono()
  .use('*', requireAuth)
  .get('/data', async (c) => {
    const user = c.get('user')
    // user is guaranteed to exist
  })
```

## Security

### CSP Headers

Applied via middleware:
- `Content-Security-Policy`: Restrictive default policy
- `X-Content-Type-Options`: nosniff
- `X-Frame-Options`: DENY
- `Referrer-Policy`: strict-origin-when-cross-origin

### Input Validation

- All input validated with Zod at API boundary via `@hono/zod-validator`
- Drizzle provides SQL injection protection via parameterized queries

### CSRF Protection

Handled automatically by Better Auth using the double-submit cookie pattern.

## File Storage (R2)

Use signed URLs for all file operations. The bucket should be private by default.

```typescript
import { getDownloadUrl, getUploadUrl } from '../lib/r2'

// Get a signed URL for downloading
const downloadUrl = await getDownloadUrl(env, 'files/document.pdf')

// Get a signed URL for uploading
const uploadUrl = await getUploadUrl(env, 'files/new-document.pdf')
```

## Database

### D1 (SQLite)

```typescript
// backend/db/schema.ts
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core'

export const users = sqliteTable('users', {
  id: text('id').primaryKey(),
  email: text('email').notNull().unique(),
  name: text('name'),
  createdAt: integer('created_at', { mode: 'timestamp' }).notNull().defaultNow(),
})
```

### PlanetScale (MySQL)

```typescript
// backend/db/schema.ts
import { mysqlTable, varchar, int, timestamp } from 'drizzle-orm/mysql-core'

export const users = mysqlTable('users', {
  id: varchar('id', { length: 255 }).primaryKey(),
  email: varchar('email', { length: 255 }).notNull().unique(),
  name: varchar('name', { length: 255 }),
  createdAt: timestamp('created_at').notNull().defaultNow(),
})
```

### Migration Commands

```bash
# Generate migration from schema changes
bun run db:generate

# Push to database (development)
bun run db:push

# Apply migrations (production)
bun run db:migrate
```
